## Create Your Account

Sign up at [dashboard.zerosettle.io](https://dashboard.zerosettle.io) and create a workspace. Each workspace represents one organization and can contain multiple apps.

After signing up, you'll be guided through onboarding: connecting Stripe, adding your first app, and creating your first product.

## Connect Stripe

ZeroSettle supports two Stripe integration modes. Choose one during onboarding:

### Managed (Express)

One-click onboarding via Stripe Express. ZeroSettle creates and manages Stripe products and prices automatically. Payouts go directly to your bank account.

- **Fee:** 5% + 50¢ per transaction
- **Setup:** Enter your business details in the Stripe Express flow
- **Best for:** New apps, fast setup, no existing Stripe account

### Bring Your Own Stripe (BYOS)

Connect your existing Stripe standard account via OAuth. Keep your products, prices, and customers. Retain full access to the Stripe dashboard for reporting and analytics.

- **Fee:** 0.5% per transaction
- **Setup:** Authorize via OAuth, then map products in the [Stripe Catalog](/iap/stripe-catalog)
- **Best for:** Apps with an existing Stripe integration

### Comparison

| | Managed (Express) | BYOS |
|---|---|---|
| **Setup time** | Minutes | 15–30 minutes |
| **ZeroSettle fee** | 5% + 50¢ | 0.5% |
| **Stripe product management** | Automatic | You manage via Stripe dashboard |
| **Existing Stripe account required** | No | Yes |
| **Full Stripe dashboard access** | No | Yes |
| **Stripe Catalog mapping** | Not needed | Required |

<Tip>
  Start with **Managed** to get up and running quickly. You can switch to BYOS at any time from your tenant settings — existing Stripe Catalog mappings are preserved.
</Tip>

## Add Your App

After connecting Stripe, add the app that will use ZeroSettle. The App Store Connect API key is not optional for an iOS app that goes live. ZeroSettle uses it to:

- generate the `apple-app-site-association` file that returns Safari-based checkouts to your app (it reads your Team ID from the key; see [Universal Links](/iap/universal-links))
- configure App Store Server Notifications for you in **ZeroSettle Managed** mode (see [Notifications and Server-Side Verification](/iap/webhooks))
- sync your apps and products from App Store Connect
- run Apple external-purchase reporting (see [External Purchase Reporting](/iap/external-purchase-reporting))

The Go Live readiness check also looks for it.

### Connect App Store Connect

Upload your App Store Connect API key to sync your apps and products.

1. In the dashboard, go to **Settings > App Store Connect**
2. Upload your `.p8` key file
3. Enter the **Key ID** and **Issuer ID** (found in App Store Connect under Users and Access > Integrations > App Store Connect API)
4. The dashboard validates your credentials and syncs your apps automatically

<Note>
  Use a key with the **App Manager** role at minimum.
</Note>

### Or create the app manually

You can add an app by hand while you build, for example before you have a key:

1. Go to **Apps** in the dashboard
2. Click **Add App**
3. Enter your app name and bundle ID (e.g., `com.yourcompany.yourapp`)

Add the App Store Connect key before you test Safari checkout or go live.

## Create Products

Add your first product from the dashboard. Each product requires:

| Field | Description |
|---|---|
| **Product ID** | Must match your App Store Connect product identifier (e.g., `com.app.premium_monthly`) |
| **Display name** | Shown to users in the checkout UI |
| **Description** | Product description |
| **Type** | Auto-renewable subscription, non-renewing subscription, consumable, or non-consumable |
| **Web price** | The price charged via web checkout |

For subscriptions, you'll also configure:

| Field | Description |
|---|---|
| **Subscription group** | Groups mutually exclusive subscription tiers (e.g., "Premium") |
| **Duration** | Billing interval — weekly, monthly, quarterly, semi-annual, or annual |

<Note>
  If you connected App Store Connect, you can sync products directly from your ASC catalog. The dashboard will pre-fill product details and keep them in sync.
</Note>

## Your API Keys

The dashboard provides publishable keys for sandbox and live environments:

| Key | Prefix | Description |
|---|---|---|
| **Sandbox** | `zs_pk_test_` | No real charges. Use during development. |
| **Live** | `zs_pk_live_` | Real payments processed via Stripe. |

The key prefix determines sandbox vs live mode — there is no separate environment toggle.

The SDK and the `/v1/iap/*` REST endpoints authenticate with your publishable key via the `X-ZeroSettle-Key` header. The dashboard also shows a secret key (`zs_sk_test_...` / `zs_sk_live_...`) for server-to-server use. Today it is accepted only by `GET /v1/iap/migration-cohort/`, which lists users eligible for the Switch & Save tip. Keep it out of your app. See [Best Practices](/iap/best-practices#api-key-usage).

Pass your publishable key to the SDK at launch:

<CodeGroup>
```swift Swift
ZeroSettle.shared.configure(.init(
    publishableKey: "zs_pk_test_..."  // Sandbox for development
))
```

```kotlin Kotlin
ZeroSettle.configure(context, ZeroSettleConfig(
    publishableKey = "zs_pk_test_..."  // Sandbox for development
))
```

```tsx React Native
await ZeroSettleKit.configure({
    publishableKey: 'zs_pk_test_...',  // Sandbox for development
});
```

```dart Flutter
await ZeroSettle.instance.configure(
    publishableKey: 'zs_pk_test_...',  // Sandbox for development
);
```
</CodeGroup>

## Keys and environments

- **Publishable key** (`zs_pk_...`): ships inside your app, so treat it as public. The SDK and the `/v1/iap/*` endpoints use it in the `X-ZeroSettle-Key` header. Anyone who has it can call those endpoints, so never rely on it alone to protect something on your server. See [Best Practices](/iap/best-practices#api-key-usage).
- **Secret key** (`zs_sk_...`): server only. On the current API it is accepted only by `GET /v1/iap/migration-cohort/`.
- **Sandbox and live are separate environments.** The key prefix picks the environment. Products, event webhook endpoints and App Store Server Notifications settings are per environment, so set each one up again for live. See [Go-Live Checklist](/iap/go-live).
- **Live needs approval.** A new account is not approved for live transactions. Until you complete Go Live, live requests return HTTP 403 with the code `not_whitelisted`. See [Get approved for live](/iap/go-live#get-approved-for-live).
- **Purchases from TestFlight, Xcode and App Review** made with a live key stay in Live and are marked as test purchases. See [Testing](/iap/testing#live-mode-test-purchases-and-testflight).

For the REST authentication details and error codes, see the [API introduction](/api-reference/introduction). For event endpoints and signing, see [Event Webhooks](/iap/event-webhooks).

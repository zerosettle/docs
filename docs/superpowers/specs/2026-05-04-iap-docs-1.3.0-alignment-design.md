# IAP Docs Alignment to Current SDK (post-1.2.4 / 1.3.0) — Design

**Status:** Approved 2026-05-04
**Author:** Brainstorm session — Ryan + Claude
**Implementation target:** Single sweep PR against the docs repo

## Context

ZeroSettleKit released 1.2.4 (Apr 28) replacing `bootstrap(_:)` with `identify(_ identity: Identity)`, renaming `claimEntitlement` to `transferStoreKitOwnershipToCurrentUser`, and adding no-arg variants for ~15 user-scoped methods. Backend just shipped 1.3.0-aware deferred-mode endpoints plus a dashboard three-mode payment-methods picker (Automatic / Wallets-only / Custom) where Custom requires SDK 1.3.0+ at the consumer.

The IAP documentation has not kept pace. An audit found 21 of 38 IAP MDX pages reference deprecated APIs or stale versions; zero pages need removal. The dashboard's new three-mode picker has zero documentation. This spec aligns the docs to the current SDK surface in a single sweep.

## Goals

1. Every SDK code example in `/iap/*.mdx` uses post-1.2.4 canonical patterns.
2. Each deprecated API that still appears (only in `migration-guide.mdx` after this work) carries a Mintlify deprecation callout pointing to the modern equivalent.
3. The 1.3.0 surface visible to users — three-mode picker + Custom-mode SDK requirement — is documented.
4. Stale version references (1.1.5 in installation, 1.1.x in entitlement-ownership history) updated to current.

## Non-goals

* Removing pages. The audit found zero remove candidates; concepts that looked overlapping (offer-manager / offer-tip-view / migration-manager / switch-and-save / upgrade-offer) all serve distinct surfaces.
* Restructuring the IAP section. `docs.json` navigation stays as-is, except for adding the new `payment-methods.mdx` page.
* Documenting deferred-mode internals as a primary concept. It's a SDK→backend optimization invisible to consumers; mentioning it in the migration-guide 1.3.0 entry is enough.
* Updating non-IAP sections (`skill-escrow`, `ai-tools`, etc.).

## Canonical modern API patterns

The "north star" every example aligns to. Defined here once; the implementation plan references this block.

### Initialization

```swift
// ✓ MODERN (post-1.2.4)
ZeroSettle.shared.configure(.init(publishableKey: "your_key"))

// Three Identity cases:
try await ZeroSettle.shared.identify(.user(id: "user_123"))   // authenticated user
try await ZeroSettle.shared.identify(.anonymous)              // guest; SDK generates UUID
try await ZeroSettle.shared.identify(.deferred)               // auth resolves later
```

### User-scoped methods (no userId param)

After `identify(_:)`, methods that previously required a `userId:` parameter accept zero args:

```swift
// ✓ MODERN
ZeroSettle.shared.transferStoreKitOwnershipToCurrentUser(productId: "...")
ZeroSettle.shared.restoreEntitlements()
ZeroSettle.shared.cancelSubscription(productId: "...")
ZeroSettle.shared.fetchProducts()
ZeroSettle.shared.fetchUserOffer()
ZeroSettle.shared.acceptSaveOffer(productId: "...")
ZeroSettle.shared.pauseSubscription(productId: "...")
ZeroSettle.shared.resumeSubscription(productId: "...")
// (plus 7 more per the 1.2.4 changelog)
```

### Deprecated forms (NOT shown in examples — only in migration-guide deprecation callouts)

```swift
// ✗ DEPRECATED
try await ZeroSettle.shared.bootstrap(userId: "...")              // → identify(.user(id:))
try await ZeroSettle.shared.identify(userId: "...")               // → identify(.user(id:))
ZeroSettle.shared.claimEntitlement(productId: "...")              // → transferStoreKitOwnershipToCurrentUser
ZeroSettle.shared.restoreEntitlements(userId: "...")              // → no-arg variant
// (and all userId-accepting overloads on the 15 methods deprecated in 1.2.4)
```

### Android / Flutter

Each platform's idiomatic equivalents follow the same pattern. The implementation plan will spot-check the Android and Flutter SDK source to confirm the exact method names and align platform-specific examples in `quickstart-android.mdx`, `quickstart-flutter.mdx`, and per-feature pages with `<CodeGroup>` blocks.

## New content

### New page: `iap/payment-methods.mdx`

Mintlify page in the IAP section, icon `credit-card`. Sits between `checkout-branding.mdx` and `payouts.mdx` in `docs.json` navigation.

Sections:

* **Overview** — the three modes (Automatic / Wallets-only / Custom) at a glance, with a recommendation matrix (use Automatic unless X, use Wallets-only when Y, use Custom when Z).
* **Automatic mode** — what shows, who picks (Stripe), why this is the recommended default. The "let Stripe decide" pitch.
* **Wallets-only mode** — what it is, the buyer-without-wallet failure mode (no card form fallback), when it's appropriate.
* **Custom mode** — full per-method control, how to configure each toggle in the dashboard, **Mintlify `<Note>` callout: "Requires ZeroSettleKit 1.3.0+. Apps on older SDK versions will see only Card / Apple Pay / Google Pay regardless of which methods you enable here."**
* **Method reference table** — methods (card, apple_pay, google_pay, link, klarna, paypal, cash_app_pay, amazon_pay, sepa_debit, etc.) with WKWebView compatibility notes per method (popup-incompatible methods marked).
* **Cross-links** — back to `checkout-branding.mdx` (logo / colors) and forward to `dashboard.mdx`.

### Updated section: `migration-guide.mdx` 1.3.0 entry

Add a top-of-page entry for SDK 1.3.0:

* "Custom payment configurations now require SDK 1.3.0+. Apps on older SDK versions will silently fall back to Card / Apple Pay / Google Pay regardless of dashboard config. Tenants using Automatic or Wallets-only modes are unaffected."
* "Internal: SDK switched to deferred-mode endpoints for faster checkout warmup. No code change required; bump to 1.3.0 to opt in."

### No new architecture pages

Deferred-mode internals are not surfaced as a primary concept. The migration-guide note is the only mention.

## Style conventions

Two callout styles, used consistently across all updates:

**Deprecation:**

```mdx
<Warning>
  **Deprecated.** `bootstrap(userId:)` is deprecated as of SDK 1.2.4. Use [`identify(.user(id:))`](#identify) instead. Will be removed in 2.0.
</Warning>
```

**Version requirement:**

```mdx
<Note>
  Requires **ZeroSettleKit 1.3.0+**. On older SDK versions, the buyer sees only Card / Apple Pay / Google Pay regardless of which methods you enable here.
</Note>
```

`<Warning>` is reserved for things that will break someday (deprecations on a removal track). `<Note>` is for awareness without breakage.

Multi-platform code examples continue using `<CodeGroup>` per existing convention. **Modern API only inside CodeGroups.** Deprecated forms appear only in `migration-guide.mdx` deprecation callouts.

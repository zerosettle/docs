## Configuration

Configure the SDK early in your app's lifecycle — typically in your `main()` or root widget's `initState`:

```dart
import 'package:zerosettle/zerosettle.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await ZeroSettle.instance.configure(
    publishableKey: 'zs_pk_live_...',  // From your ZeroSettle dashboard
  );

  runApp(const MyApp());
}
```

### Configuration Options

| Parameter | Default | Description |
|-----------|---------|-------------|
| `publishableKey` | Required | Your publishable key from the dashboard |
| `syncStoreKitTransactions` | `true` | Set to `false` if using RevenueCat (iOS) |
| `appleMerchantId` | `null` | Apple Pay merchant identifier (iOS, native pay) |
| `preloadCheckout` | `false` | Preload checkout sessions after `identify()` |
| `syncPlayPurchases` | `true` | Forward Play Billing purchases to the backend (Android) |
| `playLicenseKey` | `null` | PEM-encoded Play Console public key for local signature verification (Android) |

### Sandbox vs Live Mode

Your publishable key prefix determines the mode:

- **Sandbox** (`zs_pk_test_`): Use for development. No real charges.
- **Live** (`zs_pk_live_`): Real payments processed.

## Identify the User

After `configure()`, identify the current session **before** fetching products or making a purchase. This is required — purchase and entitlement APIs throw `ZSUserNotIdentifiedException` if `identify()` has not been called.

`identify()` returns the product catalog for `Identity.user` / `Identity.anonymous`, or `null` for `Identity.deferred`.

```dart
// Authenticated user
final catalog = await ZeroSettle.instance.identify(
  Identity.user(id: currentUser.id, name: currentUser.name, email: currentUser.email),
);

// Or, if you have no auth system yet — the SDK generates a stable session UUID
final catalog = await ZeroSettle.instance.identify(Identity.anonymous());

// Or, if auth comes on a later screen — suppresses the "no user" warning
await ZeroSettle.instance.identify(Identity.deferred());
```

See [User Identity](/iap/user-identity) for choosing between these modes.

## Fetch Products

`identify()` already returns the catalog. To re-fetch later (for example after a remote config change), call `fetchProducts()`:

```dart
final catalog = await ZeroSettle.instance.fetchProducts();

for (final product in catalog.products) {
  print('${product.displayName}: ${product.webPrice?.formatted}');
}
```

You can also react to catalog changes via the `productsUpdates` stream.

## Make a Purchase

Use the unified `purchase()` method. It routes automatically to web checkout (Stripe) or the native store (StoreKit on iOS, Play Billing on Android) depending on jurisdiction and remote config. Identity comes from the prior `identify()` call — no `userId` parameter.

```dart
try {
  final transaction = await ZeroSettle.instance.purchase(
    productId: product.id,
  );
  print('Purchased: ${transaction.productId}');
  // Unlock content
} on ZSCancelledException {
  // User cancelled — do nothing
} on ZSCheckoutFailedException catch (e) {
  print('Checkout failed: ${e.message}');
}
```

<Note>
  `presentPaymentSheet()` is **iOS-only** — it presents ZeroSettle's web payment sheet directly. On Android, payment routing goes through Google Play's User Choice Billing, so the app must not present its own sheet. Prefer the unified `purchase()` method, which works on both platforms.
</Note>

### Preloading (iOS)

For the fastest checkout experience on iOS, preload the payment sheet before the user taps "Buy". On Android these calls are no-ops:

```dart
// Call this when the paywall screen appears
await ZeroSettle.instance.warmUpPaymentSheet(productId: product.id);

// Later, when the user taps "Buy" — opens instantly
final transaction = await ZeroSettle.instance.purchase(productId: product.id);
```

## Handle Universal Link Callback

For Safari-based checkout modes, the result returns via universal link. Handle it in your app:

```dart
// In your app's universal link handler
final handled = await ZeroSettle.instance.handleUniversalLink(url);
```

See [Universal Links & Deep Links](/iap/universal-links) for the required native configuration.

## Listen for Events

Subscribe to checkout events and entitlement updates using Dart streams:

```dart
// Checkout events
ZeroSettle.instance.checkoutEvents.listen((event) {
  print('Checkout event: $event');
});

// Entitlement updates
ZeroSettle.instance.entitlementUpdates.listen((entitlements) {
  final hasPremium = entitlements.any(
    (e) => e.productId == 'premium_monthly' && e.isActive,
  );
  setState(() => _isPremium = hasPremium);
});
```

## Check Entitlements

Restore and check entitlements on app launch. After `identify()`, call `restoreEntitlements()` with no arguments:

```dart
final entitlements = await ZeroSettle.instance.restoreEntitlements();

final hasPremium = entitlements.any(
  (e) => e.productId == 'premium_monthly' && e.isActive,
);
```

For a quick single-product check, use `hasActiveEntitlement()`:

```dart
final isPremium = await ZeroSettle.instance.hasActiveEntitlement(
  productId: 'premium_monthly',
);
```

## Complete Example

```dart
import 'package:flutter/material.dart';
import 'package:zerosettle/zerosettle.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  await ZeroSettle.instance.configure(
    publishableKey: 'zs_pk_live_...',
  );

  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(home: StoreScreen());
  }
}

class StoreScreen extends StatefulWidget {
  const StoreScreen({super.key});

  @override
  State<StoreScreen> createState() => _StoreScreenState();
}

class _StoreScreenState extends State<StoreScreen> {
  List<Product> _products = [];

  @override
  void initState() {
    super.initState();
    _loadProducts();
  }

  Future<void> _loadProducts() async {
    // identify() must run before any purchase / entitlement call
    final catalog = await ZeroSettle.instance.identify(
      Identity.user(id: 'current_user_id'),
    );
    setState(() => _products = catalog?.products ?? []);
  }

  Future<void> _purchase(Product product) async {
    try {
      final transaction = await ZeroSettle.instance.purchase(
        productId: product.id,
      );
      if (mounted) {
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(content: Text('Purchased ${transaction.productId}')),
        );
      }
    } on ZSCancelledException {
      // User cancelled
    } on ZSCheckoutFailedException catch (e) {
      if (mounted) {
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(content: Text('Error: ${e.message}')),
        );
      }
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Store')),
      body: ListView.builder(
        itemCount: _products.length,
        itemBuilder: (context, index) {
          final product = _products[index];
          return ListTile(
            title: Text(product.displayName),
            subtitle: Text(product.webPrice?.formatted ?? ''),
            trailing: ElevatedButton(
              onPressed: () => _purchase(product),
              child: const Text('Buy'),
            ),
          );
        },
      ),
    );
  }
}
```

## Error Handling

The Flutter SDK uses typed exceptions (all extend the sealed `ZeroSettleException`):

| Exception | When |
|-----------|------|
| `ZSNotConfiguredException` | SDK not configured yet |
| `ZSUserNotIdentifiedException` | A user-scoped method was called before `identify()` |
| `ZSCancelledException` | User cancelled checkout |
| `ZSProductNotFoundException` | Product ID not found in catalog |
| `ZSCheckoutFailedException` | Payment failed |
| `ZSWebCheckoutDisabledException` | Web checkout disabled for this jurisdiction |
| `ZSInvalidPublishableKeyException` | The publishable key format is invalid |
| `ZSPurchasePendingException` | Purchase is pending approval (e.g. StoreKit Ask to Buy) |
| `ZSApplePayUnavailableException` | Apple-Pay-only merchant; device cannot do Apple Pay (iOS) |
| `ZSApplePaySetupRequiredException` | Apple-Pay-only merchant; Wallet has no card (iOS) |
| `ZSApiException` | Network or API error |

## Manage Subscriptions

Let users cancel or pause their subscriptions with the built-in cancel flow:

```dart
final result = await ZeroSettle.instance.presentCancelFlow(
  productId: 'premium_monthly',
);
```

<Note>
  `presentCancelFlow()` presents the native cancel-flow sheet and is currently
  implemented on **iOS only** — on Android it returns `not_implemented`. For
  Android, build the cancellation UI with the headless primitives.
</Note>

For a fully custom cancellation UI, use the headless primitives — see [Cancel Flow API](/iap/custom-cancel-flow).

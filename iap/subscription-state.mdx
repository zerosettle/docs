You can determine subscription status using the ZeroSettleKit SDK or the REST API.

## Getting subscription status via the SDK

The `entitlements` property contains all of the purchase and subscription data available about a user. This is updated whenever a purchase completes or when you call `restoreEntitlements()`.

<CodeGroup>

```swift Swift
// Identity is implicit — call identify() once first
let entitlements = try await ZeroSettle.shared.restoreEntitlements()

// Or access cached entitlements
let cached = ZeroSettle.shared.entitlements
```

```kotlin Kotlin
// Identity is implicit — call identify() once first
val entitlements = ZeroSettle.restoreEntitlements().getOrThrow()

// Or access cached entitlements (StateFlow)
val cached = ZeroSettle.entitlements.value
```

```tsx React Native
// React Native (1.3.x) still takes the userId argument
const entitlements = await ZeroSettleKit.restoreEntitlements(currentUser.id);

// Or access cached
const cached = await ZeroSettleKit.getEntitlements();
```

```dart Flutter
// Identity is implicit — call identify() once first
final entitlements = await ZeroSettle.instance.restoreEntitlements();

// Or access cached entitlements
final cached = await ZeroSettle.instance.getEntitlements();
```

</CodeGroup>

`restoreEntitlements()` performs a network request every time it is called — there is no staleness window. Call it at launch and at meaningful moments (returning from background, opening a paywall), and read the cached `ZeroSettle.shared.entitlements` everywhere else.

## Checking If A User Is Subscribed

The subscription status for a user can be determined using the `Entitlement` objects returned by `restoreEntitlements()`.

For most apps with a single premium tier, check for a specific product:

<CodeGroup>

```swift Swift
let hasPremium = entitlements.contains {
    $0.productId == "premium_monthly" && $0.isActive
}

if hasPremium {
    // user has access to premium features
}
```

```kotlin Kotlin
val hasPremium = entitlements.any {
    it.productId == "premium_monthly" && it.isActive
}

if (hasPremium) {
    // user has access to premium features
}
```

```tsx React Native
const hasPremium = entitlements.some(
  e => e.productId === 'premium_monthly' && e.isActive
);

if (hasPremium) {
  // user has access to premium features
}
```

```dart Flutter
final hasPremium = entitlements.any(
  (e) => e.productId == 'premium_monthly' && e.isActive,
);

if (hasPremium) {
  // user has access to premium features
}
```

</CodeGroup>

If your app has multiple entitlements, check if any are active:

<CodeGroup>

```swift Swift
if entitlements.contains(where: { $0.isActive }) {
    // user has access to some entitlement
}
```

```kotlin Kotlin
if (entitlements.any { it.isActive }) {
    // user has access to some entitlement
}
```

```tsx React Native
if (entitlements.some(e => e.isActive)) {
  // user has access to some entitlement
}
```

```dart Flutter
if (entitlements.any((e) => e.isActive)) {
  // user has access to some entitlement
}
```

</CodeGroup>

<Note>
  Entitlements will be empty if no purchases have been made. Always handle the empty case in your UI.
</Note>

## Restoring Purchases

Restoring purchases allows users to recover their in-app purchases on a new device or after reinstalling the app.

It is recommended that all apps have a way for users to trigger restore, even if you require accounts.

<CodeGroup>

```swift Swift
do {
    // identify() must run before restoreEntitlements()
    let entitlements = try await ZeroSettle.shared.restoreEntitlements()
    // Update UI based on entitlements
    updatePremiumAccess(entitlements)
} catch {
    // handle error
}
```

```kotlin Kotlin
// identify() must run before restoreEntitlements()
ZeroSettle.restoreEntitlements()
    .onSuccess { entitlements -> updatePremiumAccess(entitlements) }
    .onFailure { error -> /* handle error */ }
```

```tsx React Native
try {
  // React Native (1.3.x) still takes the userId argument
  const entitlements = await ZeroSettleKit.restoreEntitlements(currentUser.id);
  // Update UI based on entitlements
  updatePremiumAccess(entitlements);
} catch (error) {
  // handle error
}
```

```dart Flutter
try {
  // identify() must run before restoreEntitlements()
  final entitlements = await ZeroSettle.instance.restoreEntitlements();
  // Update UI based on entitlements
  updatePremiumAccess(entitlements);
} catch (e) {
  // handle error
}
```

</CodeGroup>

This fetches entitlements from both ZeroSettle's web checkout system and StoreKit/Play Store (if native transaction syncing is enabled).

### Anonymous Users

If your app has no auth system, identify with `Identity.anonymous` (`bootstrap('')` on React Native 1.3.x). The SDK persists a stable per-install UUID, so `restoreEntitlements()` works normally — entitlements are tied to that UUID.

This means:

- **During the session**: After a successful purchase, the SDK caches entitlements in memory. `restoreEntitlements()` also refreshes them from the server against the persisted anonymous UUID.
- **Across launches on the same install**: The anonymous UUID is persisted, so `restoreEntitlements()` recovers entitlements after the process restarts.
- **On reinstall or a new device**: The anonymous UUID is install-scoped — it does not survive an app-data clear or reinstall. Promote the user to `Identity.user(id:)` once you have an auth system for reinstall-safe, cross-device restoration.

<Warning>
  Anonymous identities are install-scoped. Users lose access to their entitlements on reinstall or a new device. Prompt users to create an account after purchase, or use the REST API to query entitlements by email. See [User Identity — Anonymous Users](/iap/user-identity#option-3-anonymous-users) for details.
</Warning>

## Cache

The SDK holds the user's entitlements **in memory** on `ZeroSettle.shared.entitlements`. That cache is not persisted to disk — it is gone when the app process terminates.

Reads of `entitlements` are free and never touch the network, so a user who unlocked something keeps access offline for the rest of the session. `restoreEntitlements()` is the opposite: it always calls the backend, with no TTL or staleness check. Don't put it behind a paywall render or a feature gate.

<Note>
  Because the cache is in-memory only, call `restoreEntitlements()` once on every app launch (or let `identify(_:)` do it) to rehydrate from the server, then read `ZeroSettle.shared.entitlements` for the rest of the session.
</Note>

<Warning>
  Entitlements are the SDK's view of what the backend and the local store know. They are not a substitute for a server-side check on anything you would mind a determined user unlocking — see [Best Practices → Security](/iap/best-practices#security).
</Warning>

## Listening For Entitlement Updates

Entitlements can change from various sources: web checkout completion, StoreKit/Play Store transaction updates, or subscription renewals/cancellations. Use the delegate to respond to changes:

<CodeGroup>

```swift Swift
// Option A: the delegate protocol
class PurchaseManager: ZeroSettleDelegate {
    init() {
        ZeroSettle.shared.delegate = self
    }

    func zeroSettleEntitlementsDidUpdate(_ entitlements: [Entitlement]) {
        // Handle any changes to entitlements
        updatePremiumUI(entitlements)
    }
}

// Option B (preferred for async/await): the entitlementUpdates stream
for await entitlements in ZeroSettle.shared.entitlementUpdates {
    updatePremiumUI(entitlements)
}
```

```kotlin Kotlin
// Android has no delegate — observe the entitlements StateFlow
ZeroSettle.entitlements
    .onEach { entitlements -> updatePremiumUI(entitlements) }
    .launchIn(scope)
```

```tsx React Native
import { useZeroSettleEvents } from 'react-native-zerosettle';

useZeroSettleEvents({
  onEntitlementsDidUpdate: (entitlements) => {
    updatePremiumUI(entitlements);
  },
});
```

```dart Flutter
ZeroSettle.instance.entitlementUpdates.listen((entitlements) {
  updatePremiumUI(entitlements);
});
```

</CodeGroup>

You can also observe state reactively in your UI framework:

<CodeGroup>

```swift SwiftUI
struct ContentView: View {
    // ZeroSettle is @Observable — reading it in `body` is tracked automatically.
    private var iap: ZeroSettle { .shared }

    var body: some View {
        if iap.entitlements.contains(where: { $0.isActive }) {
            PremiumContent()
        } else {
            UpgradePrompt()
        }
    }
}
```

```kotlin Jetpack Compose
@Composable
fun ContentScreen() {
    val entitlements by ZeroSettle.entitlements.collectAsState()

    if (entitlements.any { it.isActive }) {
        PremiumContent()
    } else {
        UpgradePrompt()
    }
}
```

```tsx React Native
import { useState } from 'react';
import { ZeroSettleKit, useZeroSettleEvents } from 'react-native-zerosettle';
import type { Entitlement } from 'react-native-zerosettle';

function ContentScreen() {
  const [entitlements, setEntitlements] = useState<Entitlement[]>([]);

  // Seed from cache, then keep in sync via the events hook
  useZeroSettleEvents({
    onEntitlementsDidUpdate: setEntitlements,
  });

  const hasAccess = entitlements.some(e => e.isActive);

  return hasAccess ? <PremiumContent /> : <UpgradePrompt />;
}
```

```dart Flutter
StreamBuilder<List<Entitlement>>(
  stream: ZeroSettle.instance.entitlementUpdates,
  builder: (context, snapshot) {
    final hasAccess = snapshot.data?.any((e) => e.isActive) ?? false;
    return hasAccess ? PremiumContent() : UpgradePrompt();
  },
)
```

</CodeGroup>

<Note>
  Entitlement updates are triggered by SDK operations (purchases, restores). They are not pushed from the backend in real-time.
</Note>

## Getting subscription status via the REST API

If you need to get a user's subscription status from outside of the ZeroSettle SDK, for example, from your own backend, you should use the REST API.

Query by user ID:

```bash
curl --request GET \
  --url https://api.zerosettle.io/v1/iap/entitlements/?user_id=app_user_id \
  --header 'Content-Type: application/json' \
  --header 'X-ZeroSettle-Key: zs_pk_live_...'
```

Query by email (for anonymous users without a user ID):

```bash
curl --request GET \
  --url https://api.zerosettle.io/v1/iap/entitlements/?email=user@example.com \
  --header 'Content-Type: application/json' \
  --header 'X-ZeroSettle-Key: zs_pk_live_...'
```

Either `user_id` or `email` is required. The email parameter is useful for recovering entitlements for [anonymous users](/iap/user-identity#option-3-anonymous-users) who purchased without a user account.

<Note>
  All API endpoints authenticate with your **publishable key** (`zs_pk_live_...` or `zs_pk_test_...`) via the `X-ZeroSettle-Key` header — the same key you use in the SDK.
</Note>

## Handling Refunds

ZeroSettle handles refunds for both subscription and non-subscription products. As soon as a refund is processed, the entitlements will be updated to reflect the correct status — no action required on your part. The `isActive` property on the affected `Entitlement` will be set to `false`.

ZeroSettle works alongside RevenueCat. You can use RevenueCat for StoreKit and Play Billing subscription management while routing eligible purchases through ZeroSettle's web checkout for lower fees.

Both ZeroSettle and RevenueCat must be identified to the same user ID before purchase. ZeroSettle is identify-first on iOS, Android, and Flutter — call `identify(...)` once after sign-in, alongside RevenueCat's `logIn(rcUserId)`. On iOS use `try await ZeroSettle.shared.identify(.user(id: rcUserId))`, on Android `ZeroSettle.identify(Identity.User(id = rcUserId))`, and on Flutter `await ZeroSettle.instance.identify(Identity.user(id: rcUserId))`.

There are two integration approaches:

## Option 1: SDK Integration (Recommended)

Use the ZeroSettleKit SDK alongside RevenueCat in your app. This gives you full control over the purchase flow.

### Configuration

Decide first whether you want ZeroSettle to see your native store purchases.

| You want | Set | Result |
|---|---|---|
| RevenueCat owns native billing; ZeroSettle only handles web checkout | `syncStoreKitTransactions: false` | ZeroSettle's dashboard shows web checkout only |
| ZeroSettle to also track your StoreKit revenue, trials, and entitlements | `syncStoreKitTransactions: true` (the default) | Both platforms observe the same purchases |

The second row is a normal, supported setup — it is how you evaluate ZeroSettle against RevenueCat on the same traffic, and how you get ZeroSettle's trial and entitlement telemetry without moving checkout. The two SDKs do not fight over StoreKit: `Transaction.updates` is a broadcast sequence that delivers to every listener, and `transaction.finish()` is idempotent. What you get is the same purchase reported to two analytics backends, which is exactly the point.

Turn the listener **off** only when you specifically do not want native purchases in ZeroSettle's numbers.

The examples below show the web-checkout-only setup:

<CodeGroup>
```swift Swift
import ZeroSettleKit
import RevenueCat

@main
struct YourApp: App {
    init() {
        // Configure RevenueCat first
        Purchases.configure(withAPIKey: "your_revenuecat_key")

        // Configure ZeroSettle with StoreKit sync disabled
        ZeroSettle.shared.configure(.init(
            publishableKey: "your_zerosettle_key",
            syncStoreKitTransactions: false  // RevenueCat manages StoreKit
        ))
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
                .zeroSettleHandler()
        }
    }
}
```

```kotlin Kotlin
import com.zerosettle.sdk.ZeroSettle
import com.zerosettle.sdk.ZeroSettleConfig
import com.revenuecat.purchases.Purchases
import com.revenuecat.purchases.PurchasesConfiguration

class MyApp : Application() {
    override fun onCreate() {
        super.onCreate()

        // Configure RevenueCat first
        Purchases.configure(
            PurchasesConfiguration.Builder(this, "your_revenuecat_key").build()
        )

        // Configure ZeroSettle with Play Billing sync disabled
        ZeroSettle.configure(this, ZeroSettleConfig(
            publishableKey = "your_zerosettle_key",
            syncPlayPurchases = false,  // RevenueCat manages Play Billing
        ))
    }
}
```

```tsx React Native

import Purchases from 'react-native-purchases';

// Configure RevenueCat first
Purchases.configure({ apiKey: 'your_revenuecat_key' });

// Configure ZeroSettle with StoreKit sync disabled
await ZeroSettleKit.configure({
  publishableKey: 'your_zerosettle_key',
  syncStoreKitTransactions: false,
});
```

```dart Flutter

import 'package:purchases_flutter/purchases_flutter.dart';

```
</CodeGroup>

<Note>
  If you leave the listener on, also read [Analytics-Only Integration](/iap/analytics-only) — it covers the one thing that is genuinely easy to miss: a purchase your own code makes with `Product.purchase()` is not redelivered through `Transaction.updates`, so it reaches ZeroSettle on the next `identify(_:)` rather than immediately.
</Note>

### User Identity

Use RevenueCat's `appUserID` as the user ID for ZeroSettle. This links web checkout purchases to the correct RevenueCat customer. Identify ZeroSettle with the same ID on every platform.

<CodeGroup>
```swift Swift
let rcUserId = Purchases.shared.appUserID

// Identify ZeroSettle with the same user ID (do this once after sign-in)
try await ZeroSettle.shared.identify(.user(id: rcUserId))

// Fetch ZeroSettle product catalog
let catalog = try await ZeroSettle.shared.fetchProducts()

// Purchase via web checkout using .checkoutSheet() in your SwiftUI view:
// .checkoutSheet(item: $selectedProduct) { result in ... }
```

```kotlin Kotlin
val rcUserId = Purchases.sharedInstance.appUserID

// Identify ZeroSettle with the same user ID (do this once after sign-in)
ZeroSettle.identify(Identity.User(id = rcUserId))

// Fetch ZeroSettle product catalog
val catalog = ZeroSettle.fetchProducts().getOrThrow()

// Purchase via web checkout
ZeroSettle.purchase(
    activity = this,
    productId = product.id,
).onSuccess { transaction -> /* unlock content */ }
```

```tsx React Native
const rcUserId = await Purchases.getAppUserID();

const catalog = await ZeroSettleKit.fetchProducts(rcUserId);

const transaction = await ZeroSettleKit.purchase(product.id, rcUserId);
```

```dart Flutter
final rcUserId = await Purchases.appUserID;

// Identify ZeroSettle with the same user ID (do this once after sign-in)
await ZeroSettle.instance.identify(Identity.user(id: rcUserId));

final catalog = await ZeroSettle.instance.fetchProducts();

final transaction = await ZeroSettle.instance.purchase(
  productId: product.id,
);
```
</CodeGroup>

### Hybrid Paywall

Show both ZeroSettle (web checkout) and RevenueCat (StoreKit/Play Billing) purchase options:

<CodeGroup>
```swift Swift
struct PaywallView: View {
    @State private var selectedProduct: ZSProduct?
    let zsProduct: ZSProduct    // From ZeroSettleKit
    let rcPackage: Package        // From RevenueCat

    var body: some View {
        VStack(spacing: 16) {
            // Web checkout — lower fees
            Button("Subscribe — \(zsProduct.webPrice?.formatted ?? "")") {
                selectedProduct = zsProduct
            }
            .checkoutSheet(
                item: $selectedProduct
            ) { result in
                // The completion handler is not async — hop into a Task.
                if case .success = result {
                    Task {
                        // Refresh RC customer info to pick up the webhook
                        _ = try? await Purchases.shared.customerInfo()
                    }
                }
            }

            // StoreKit fallback via RevenueCat
            Button("Subscribe via App Store — \(rcPackage.localizedPriceString)") {
                Task {
                    try? await Purchases.shared.purchase(package: rcPackage)
                }
            }
            .foregroundStyle(.secondary)
        }
    }
}
```

```kotlin Kotlin
@Composable
fun PaywallScreen(zsProduct: Product, rcPackage: Package) {
    val context = LocalContext.current
    val scope = rememberCoroutineScope()

    Column(verticalArrangement = Arrangement.spacedBy(16.dp)) {
        // Web checkout — lower fees
        Button(onClick = {
            scope.launch {
                ZeroSettle.purchase(
                    activity = context as Activity,
                    productId = zsProduct.id,
                ).onSuccess {
                    // Refresh RC customer info to pick up the webhook
                    Purchases.sharedInstance.getCustomerInfo(
                        object : ReceiveCustomerInfoCallback { /* ... */ }
                    )
                }.onFailure { e ->
                    if (e !is ZeroSettleError.PurchaseCancelled) showError(e.message)
                }
            }
        }) {
            Text("Subscribe — ${zsProduct.webPrice?.formatted}")
        }

        // Play Store fallback via RevenueCat
        TextButton(onClick = {
            scope.launch {
                Purchases.sharedInstance.purchase(
                    PurchaseParams.Builder(context as Activity, rcPackage).build(),
                    object : PurchaseCallback { /* ... */ }
                )
            }
        }) {
            Text("Subscribe via Play Store — ${rcPackage.product.price.formatted}")
        }
    }
}
```

```tsx React Native
// Web checkout — lower fees
const handleWebPurchase = async () => {
  try {
    await ZeroSettleKit.purchase(zsProduct.id, Purchases.getAppUserID());
    // Refresh RC customer info
    await Purchases.getCustomerInfo();
  } catch (e) {
    if (e.code !== 'cancelled') showError(e.message);
  }
};

// StoreKit/Play Store fallback via RevenueCat
const handleStorePurchase = async () => {
  await Purchases.purchasePackage(rcPackage);
};
```

```dart Flutter
// Web checkout — lower fees
try {
  final transaction = await ZeroSettle.instance.purchase(
    productId: zsProduct.id,
  );
  // Refresh RC customer info
  await Purchases.getCustomerInfo();
} on ZSCancelledException {
  // User cancelled
}

// StoreKit/Play Store fallback via RevenueCat
await Purchases.purchasePackage(rcPackage);
```
</CodeGroup>

## Option 2: RevenueCat Paywall Custom Button

If you use RevenueCat's paywall builder, you can add a custom checkout button that links to ZeroSettle's hosted checkout:

1. In your RevenueCat paywall template, add a purchase button with **custom checkout**
2. Set the URL to your ZeroSettle checkout link
3. Configure a URL scheme in your app to handle the callback

### Handle the Callback

<CodeGroup>
```swift Swift
@main
struct YourApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .onOpenURL { url in
                    if url.scheme == "yourapp" {
                        let status = url.lastPathComponent
                        switch status {
                        case "success":
                            // Refresh RevenueCat customer info
                            Task {
                                try? await Purchases.shared.customerInfo()
                            }
                        case "cancelled":
                            break
                        default:
                            break
                        }
                    }
                }
        }
    }
}
```

```kotlin Kotlin
// In your Activity that handles the deep link
override fun onNewIntent(intent: Intent?) {
    super.onNewIntent(intent)
    intent?.data?.let { uri ->
        if (uri.scheme == "yourapp") {
            when (uri.lastPathSegment) {
                "success" -> {
                    // Refresh RevenueCat customer info
                    Purchases.sharedInstance.getCustomerInfo(
                        object : ReceiveCustomerInfoCallback {
                            override fun onReceived(customerInfo: CustomerInfo) {
                                updateUI(customerInfo)
                            }
                            override fun onError(error: PurchasesError) { }
                        }
                    )
                }
                "cancelled" -> { /* no-op */ }
            }
        }
    }
}
```

```tsx React Native
import { Linking } from 'react-native';
import Purchases from 'react-native-purchases';

Linking.addEventListener('url', async ({ url }) => {
  const parsed = new URL(url);
  if (parsed.pathname.endsWith('success')) {
    await Purchases.getCustomerInfo();
  }
});
```

```dart Flutter
// Handle deep link callback
void handleDeepLink(Uri uri) async {
  if (uri.pathSegments.last == 'success') {
    await Purchases.getCustomerInfo();
  }
}
```
</CodeGroup>

<Note>
  The SDK integration (Option 1) provides a better user experience since the payment sheet stays inside your app. The custom button approach is useful if you want to use RevenueCat's paywall builder without writing custom UI code.
</Note>

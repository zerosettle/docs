## Configuration

Configure the SDK early in your app's lifecycle — typically in your `Application.onCreate()`:

```kotlin
import com.zerosettle.sdk.ZeroSettle
import com.zerosettle.sdk.ZeroSettleConfig

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()

        ZeroSettle.configure(
            this,
            ZeroSettleConfig(
                publishableKey = "zs_pk_live_…"  // From your ZeroSettle dashboard
            )
        )
    }
}
```

### Configuration Options

`ZeroSettleConfig` is a top-level data class:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `publishableKey` | Required | Your publishable key from the dashboard |
| `playLicenseKey` | `null` | Optional PEM RSA key for advisory Play `Purchase.signature` checks |
| `syncPlayPurchases` | `true` | Set to `false` if another library (e.g. RevenueCat) fully owns Play Billing |
| `preloadCheckout` | `false` | Eagerly fetch web checkout config after `identify()` |
| `strictAck` | `false` | Never acknowledge a Play purchase without backend validation (see the [acknowledgement model](/sdk/android/acknowledgement-model)) |
| `baseUrlOverride` | `null` | Dev-only — point the SDK at a local backend |

### Sandbox vs Live Mode

Your publishable key prefix determines the mode — there is no separate flag:

- **Sandbox** (`zs_pk_test_`): Use for development. No real charges.
- **Live** (`zs_pk_live_`): Real payments processed.

## Identify the user

The SDK is **identify-first** — call `ZeroSettle.identify(...)` before any product-fetch or purchase call. `identify()` bootstraps the SDK: syncs Play purchases, fetches the catalog, and restores entitlements.

```kotlin
import com.zerosettle.sdk.Identity

lifecycleScope.launch {
    val result = ZeroSettle.identify(
        Identity.User(id = currentUser.id, name = displayName, email = email)
    )
}
```

`id` need not be a UUID — the SDK derives a deterministic UUIDv5 `appAccountToken` from it. Use `Identity.Anonymous` for a stable per-install UUID, or `Identity.Deferred` to defer identification.

## Fetch Products

Once a user is identified, the catalog is already loaded into `ZeroSettle.products`. To re-fetch:

```kotlin
val catalog = ZeroSettle.fetchProducts().getOrThrow()  // Result<ProductCatalog>

for (product in catalog.products) {
    println("${product.displayName}: ${product.webPrice}")
}
```

<Note>
  `identify()` and `fetchProducts()` are `suspend` functions — call them from a coroutine scope. They resolve against the identified user; there are no `userId` parameter overloads.
</Note>

## Make a Purchase

`purchase()` drives the full web checkout flow and returns a `Result<CheckoutTransaction>`. The user pays via a Chrome Custom Tab (default), an in-app WebView, or the external browser.

```kotlin
import com.zerosettle.sdk.ZeroSettle
import com.zerosettle.sdk.models.ZeroSettleError

val result = ZeroSettle.purchase(activity = this, productId = product.id)
result
    .onSuccess { txn -> /* unlock content — txn.productId */ }
    .onFailure { e ->
        when (e) {
            is ZeroSettleError.PurchaseCancelled -> { /* user cancelled */ }
            is ZeroSettleError.CheckoutFailed -> showError(e.message)
            else -> showError(e.message)
        }
    }
```

The checkout presentation (Custom Tab, WebView, or external browser) is controlled by your dashboard config; you can override per-call with the optional `presentation` parameter.

### Native Play Billing

To trigger a native Google Play Billing purchase instead of web checkout, use `purchaseViaPlayBilling()` — see [Play Billing Integration](/iap/play-billing-integration).

### Jetpack Compose

```kotlin
@Composable
fun PurchaseButton(product: Product) {
    val context = LocalContext.current
    val scope = rememberCoroutineScope()

    Button(onClick = {
        scope.launch {
            ZeroSettle.purchase(activity = context as Activity, productId = product.id)
                .onSuccess { /* handle success */ }
                .onFailure { /* handle error */ }
        }
    }) {
        Text("Buy ${product.displayName}")
    }
}
```

## Handle Deep Link Callback

For Custom Tab or external browser checkout, the result returns to your app via a `zerosettle://checkout/…` deep link. Forward it back into the SDK with `completeWebCheckout()`:

```kotlin
class MainActivity : ComponentActivity() {
    override fun onNewIntent(intent: Intent) {
        super.onNewIntent(intent)
        intent.data?.toString()?.let { url ->
            lifecycleScope.launch { ZeroSettle.completeWebCheckout(url) }
        }
    }
}
```

### AndroidManifest.xml

Register the deep link intent filter:

```xml
<activity android:name=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="zerosettle" android:host="checkout" />
    </intent-filter>
</activity>
```

<Note>
  Chrome Custom Tabs don't notify your app when the user dismisses them. Activities that are a `LifecycleOwner` (every modern `ComponentActivity` / `AppCompatActivity`) get auto-cancel for free; other hosts should call `ZeroSettle.releasePendingCheckout()` from `onResume()`.
</Note>

## Listen for Events

Observe state reactively with Kotlin `StateFlow` / `SharedFlow` — there is no delegate interface on Android.

```kotlin
// Entitlements — a StateFlow<List<Entitlement>>
ZeroSettle.entitlements.collect { entitlements ->
    val hasPremium = entitlements.any {
        it.productId == "premium_monthly" && it.isActive
    }
    _uiState.value = _uiState.value.copy(isPremium = hasPremium)
}

// Structured analytics events — a SharedFlow<ZeroSettleEvent>
ZeroSettle.events.collect { event ->
    when (event) {
        is ZeroSettleEvent.PurchaseSucceeded -> { /* … */ }
        is ZeroSettleEvent.EntitlementsRefreshed -> { /* … */ }
        else -> Unit
    }
}
```

## Check Entitlements

`identify()` already restores entitlements. To re-fetch them, or to check synchronously:

```kotlin
ZeroSettle.restoreEntitlements()  // suspend — Result<List<Entitlement>>

val hasPremium = ZeroSettle.hasActiveEntitlement("premium_monthly")
```

## Complete Example

```kotlin
import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import com.zerosettle.sdk.Identity
import com.zerosettle.sdk.ZeroSettle
import com.zerosettle.sdk.ZeroSettleConfig
import com.zerosettle.sdk.models.Product
import kotlinx.coroutines.launch

class StoreActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        ZeroSettle.configure(
            this,
            ZeroSettleConfig(publishableKey = "zs_pk_live_…")
        )

        setContent { StoreScreen(activity = this) }
    }
}

@Composable
fun StoreScreen(activity: ComponentActivity) {
    var products by remember { mutableStateOf<List<Product>>(emptyList()) }
    val scope = rememberCoroutineScope()
    val snackbarHostState = remember { SnackbarHostState() }

    LaunchedEffect(Unit) {
        // identify-first — bootstraps the SDK and loads the catalog
        ZeroSettle.identify(Identity.User(id = "current_user_id"))
        products = ZeroSettle.products.value
    }

    Scaffold(
        topBar = { TopAppBar(title = { Text("Store") }) },
        snackbarHost = { SnackbarHost(snackbarHostState) },
    ) { padding ->
        LazyColumn(modifier = Modifier.padding(padding)) {
            items(products) { product ->
                ListItem(
                    headlineContent = { Text(product.displayName) },
                    trailingContent = {
                        Button(onClick = {
                            scope.launch {
                                ZeroSettle.purchase(
                                    activity = activity,
                                    productId = product.id,
                                )
                                    .onSuccess { txn ->
                                        snackbarHostState.showSnackbar("Purchased ${txn.productId}")
                                    }
                                    .onFailure { e ->
                                        snackbarHostState.showSnackbar("Error: ${e.message}")
                                    }
                            }
                        }) {
                            Text("Buy")
                        }
                    },
                )
            }
        }
    }
}
```

## Error Handling

`ZeroSettle` public methods return `kotlin.Result<T>` — they never throw for normal errors. Failures carry a `ZeroSettleError`, a sealed class:

| Case | When |
|-----------|------|
| `ZeroSettleError.NotConfigured` | `configure()` not called |
| `ZeroSettleError.UserNotIdentified` | `identify()` not called before this API |
| `ZeroSettleError.PurchaseCancelled` | User cancelled checkout |
| `ZeroSettleError.CheckoutInFlight` | A web checkout is already in progress |
| `ZeroSettleError.ProductNotFound` | Product ID not found in catalog |
| `ZeroSettleError.CheckoutFailed` | Payment failed |
| `ZeroSettleError.PlayBillingError` | A Google Play Billing error (carries `responseCode`) |
| `ZeroSettleError.PurchasePending` | Play purchase pending Google review (parental approval, etc.) |
| `ZeroSettleError.JurisdictionBlocked` | Web checkout unavailable in the user's jurisdiction |
| `ZeroSettleError.BackendError` / `NetworkError` | API / network errors |

## Subscription Management

Cancel, pause, and resume subscriptions through headless `:core` calls:

```kotlin
ZeroSettle.cancelSubscription(productId = "premium_monthly")  // Result<Unit>
ZeroSettle.pauseSubscription(productId = "premium_monthly", pauseDurationDays = 30)
ZeroSettle.resumeSubscription(productId = "premium_monthly")
```

For a drop-in cancel-flow UI (save-offer aware), use the `ZeroSettleCancelFlow` Composable from the optional `:ui` module.

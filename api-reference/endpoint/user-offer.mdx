## When to use this

`GET /iap/user-offer/` is the canonical offer + subscription-state endpoint introduced
with **SDK 1.2+**. A single request returns:

- The user's **current subscription state** as a tagged union (`subscription.type`
  is the discriminator — `none`, `active_web`, `active_storekit`,
  `migration_trial`, or `cancelled_active`).
- Exactly **one offer decision** keyed by `offer.action_type`
  (`no_action`, `migrate_storekit_to_web`, `upgrade_storekit_to_web`, or
  `upgrade_web_to_web`). `is_eligible` is `false` iff `action_type` is `no_action`.

It replaces the overlapping legacy surface of:

| Legacy endpoint | What it still does |
| --- | --- |
| [`GET /iap/products/`](/api-reference/endpoint/get-products) `config.migration` / `config.offer` | Old SDKs continue to read these fields. They are now derived from the same resolver — the wire format is byte-identical. |
| [`GET /iap/upgrade-offer/`](/api-reference/endpoint/get-upgrade-offer) | Still supported for SDKs &lt;1.2. Derives from the same resolver. |
| `/iap/storekit-subscription-status/` status parsing | Prefer `offer.apple_subscription.is_active` on the user-offer response, or the new `is_active` / `auto_renew_enabled` booleans on [that endpoint](/api-reference/endpoint/get-storekit-subscription-status). |

SDK 1.2+ apps should call `/iap/user-offer/` and ignore the legacy fields.
Older SDKs are unaffected — the legacy contracts remain fully supported.

## Discriminated response

`offer.action_type` is the discriminator. Clients are expected to exhaustively
handle every variant. Pattern-match on `action_type` first; only read
`checkout_product_id`, `savings_percent`, `proration`, etc. inside the branches
where they are meaningful.

### Example: `no_action`

User has no active subscription, is not eligible for any offer, or the app has no
campaign configured.

```json
{
  "user_id": "user_abc123",
  "app_id": 42,
  "is_sandbox": false,
  "subscription": { "type": "none" },
  "offer": {
    "action_type": "no_action",
    "is_eligible": false,
    "checkout_product_id": "",
    "from_product_id": null,
    "savings_percent": 0,
    "free_trial_days": 0,
    "min_subscription_days": 0,

    "proration": null,

    "experiment_variant_id": null

}
```

## Error responses

- **400** — `user_id` query parameter is missing or empty.
- **401** — `X-ZeroSettle-Key` header is missing or invalid.
- **404** — The supplied `user_id` has no identity associated with this app.

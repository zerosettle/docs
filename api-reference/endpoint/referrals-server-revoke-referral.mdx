---
title: 'Revoke Referral'
openapi: 'POST /referrals/referrals/{referral_id}/revoke/'
---

Cancels a referral, from your server. Use it when you find abuse the automatic checks missed.

## Request

Send your secret key and an `Idempotency-Key` header.

| Field | Notes |
|---|---|
| `reason` | Required. `fraud`, `self_referral`, `same_payer`, `device_reused`, `refunded`, `merged_existing_user` or `other` |
| `note` | Your note, kept with the record. Required when `reason` is `other` |

## What happens

A referral that has not paid out stops counting. A referral that already earned a reward takes the reward back: the granted access ends, or the credits left are removed. Revoking a referral that is already revoked changes nothing and returns it.

A revoke sends `referral.revoked`, and `referral_reward.revoked` for each reward taken back. See [Event Webhooks](/iap/event-webhooks#referral-events).

## Errors

Every error uses one shape:

```json
{ "error": { "code": "not_found", "message": "No referral or reward has this id.", "retryable": false } }
```

| Status | Code | Meaning |
|---|---|---|
| 400 | `invalid_request` | The body is not valid, or `reason` is not one of the values above |
| 400 | `note_required` | `reason` is `other` and there is no note |
| 400 | `idempotency_key_required` | The `Idempotency-Key` header is missing |
| 401 | `secret_key_required` | No key, a publishable key, or a key that is not valid |
| 404 | `not_found` | No referral has this id in this project and environment |
| 409 | `idempotency_key_reused`, `request_in_progress` | See [Create Access Grant](/api-reference/endpoint/create-access-grant#errors) |

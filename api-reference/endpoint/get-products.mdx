## Trial mode object

When `user_id` is included in the request, every `auto_renewable_subscription` product that has a free trial configured includes a `trial` field. It is present whether or not the user is still eligible, so also check `is_trial_eligible`. The object contains:

| Field | Type | Description |
|---|---|---|
| `mode` | `"free" \| "paid" \| "auth_hold"` | How the trial is collected (see below). |
| `duration` | string | Duration token (e.g. `1_week`, `3_days`, `1_month`). Maps to the trial length; the app controls how this is displayed. |
| `upfront_amount_cents` | integer | Cents charged immediately at checkout. Non-zero only for `paid` mode. |
| `hold_amount_cents` | integer | Cents placed as an authorization hold. Non-zero only for `auth_hold` mode. |
| `validates_card` | boolean | `true` for `paid` and `auth_hold` (a real or pending charge verifies the payment method); `false` for `free`. |

**`trial.mode` semantics:**

- `free` — No charge during the trial. The payment method is saved at checkout and billed at trial end for the full subscription price.
- `paid` — A real charge of `upfront_amount_cents` is collected immediately and kept. The full subscription price is then billed at trial end.
- `auth_hold` — A temporary authorization hold of `hold_amount_cents` is placed (shown as a pending charge in the customer's bank). The hold is released when the subscription converts or is cancelled. The trial itself costs nothing.

The `trial` object is **absent** (not null) for:
- Non-subscription products
- Subscription products with no trial configured
- Requests without a `user_id`

`is_trial_eligible` is the per-user answer. It is `null` when no `user_id` was sent, when the product has no trial, or when the product is not in a subscription family.

## Response shape

The response is `{"products": [...], "config": {"checkout": {...}, "migration": {...}|null, "offer": {...}|null}}`. Checkout presentation and any Switch & Save or upgrade offer live under `config`. Use `checkout_route` on each product: `store` means a routing experiment sent this user to the store, so do not offer web checkout.

**App responsibility:** These fields are facts about the payment mechanics. The app owns all trial copy and UI — ZeroSettle does not supply copy strings.

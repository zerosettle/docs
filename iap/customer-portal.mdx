ZeroSettle gives your customers two ways to manage their subscriptions: an
in-app **cancel flow** (a backend-driven retention sheet) and a Stripe-powered
billing portal reached through the links in ZeroSettle's transactional emails.

## In-App Subscription Management

ZeroSettle subscriptions are managed in-app through the **cancel flow** — a
backend-driven retention sheet that collects feedback, optionally presents a
save offer, and lets the user cancel or pause. There is no standalone "open
customer portal" SDK call; the Stripe portal is reachable via the email links
described below.

<Note>
  Earlier SDK versions exposed `showManageSubscription()` and
  `openCustomerPortal()`. These have been removed. Use the cancel flow
  (`.retentionSheet` / `presentCancelFlow`) for ZeroSettle (web) subscriptions,
  and the platform's native subscription settings for store-billed
  subscriptions (see below).
</Note>

### SwiftUI Modifier (iOS)

The simplest way to add subscription management on iOS is the
`.retentionSheet(isPresented:onResult:)` modifier. It presents the cancel flow
sheet — questionnaire, save offer, and pause options:

```swift Swift
@State private var showManageSubscription = false

Button("Manage Subscription") {
    showManageSubscription = true
}
.retentionSheet(isPresented: $showManageSubscription) { result in
    // Handle the retention result (cancelled, retained, paused, dismissed)
}
```

### Cancel Flow Across Platforms

On Android, Flutter, and React Native, present subscription management with the
cancel flow described in the [Cancel Flow](#cancel-flow) section below.
Identity is implicit on iOS, Android, and Flutter — call `identify()` once at
startup; React Native (1.3.x) still takes a `userId`.

### Native Store Subscriptions

For subscriptions billed through Apple or Google (StoreKit / Play Store), route
users to the platform's own subscription settings:

<CodeGroup>

```swift Swift
// Apple billing — open the system subscription management sheet
import StoreKit

if let scene = UIApplication.shared.connectedScenes
    .first(where: { $0 is UIWindowScene }) as? UIWindowScene {
    try await AppStore.showManageSubscriptions(in: scene)
}
```

```kotlin Kotlin
// Google Play billing — open the Play subscription center
val intent = Intent(
    Intent.ACTION_VIEW,
    Uri.parse("https://play.google.com/store/account/subscriptions"),
)
context.startActivity(intent)
```

</CodeGroup>

## Auto-Refresh

Entitlements are automatically refreshed when the cancel flow is dismissed. Any
subscription changes the user makes (cancellation, pause, re-subscribe) are
reflected in `ZeroSettle.shared.entitlements` (iOS) /
`ZeroSettle.entitlements` (Android) and emitted to the entitlement update
stream.

<CodeGroup>

```swift Swift
// Entitlements stay in sync automatically after the cancel flow dismisses
let entitlements = ZeroSettle.shared.entitlements
let hasAccess = entitlements.contains { $0.isActive }
```

```kotlin Kotlin
// Entitlements stay in sync automatically after the cancel flow dismisses
val entitlements by ZeroSettle.entitlements.collectAsState()
val hasAccess = entitlements.any { it.isActive }
```

```tsx React Native
const entitlements = await ZeroSettleKit.getEntitlements();
const hasAccess = entitlements.some(e => e.isActive);
```

```dart Flutter
final entitlements = await ZeroSettle.instance.getEntitlements();
final hasAccess = entitlements.any((e) => e.isActive);
```

</CodeGroup>

## Observing Changes

There are no cancel-flow-specific callbacks. Instead, observe entitlement
updates to react when a user modifies their subscription:

<CodeGroup>

```swift Swift
// iOS uses the ZeroSettleDelegate protocol
class MyDelegate: ZeroSettleDelegate {
    func zeroSettleEntitlementsDidUpdate(_ entitlements: [Entitlement]) {
        // Entitlements refreshed after the cancel flow
        updatePremiumUI(entitlements)
    }
}
```

```kotlin Kotlin
// Android exposes entitlements as a StateFlow — collect it
scope.launch {
    ZeroSettle.entitlements.collect { entitlements ->
        // Entitlements refreshed after the cancel flow
        updatePremiumUI(entitlements)
    }
}
```

```tsx React Native
// Subscribe with the useZeroSettleEvents hook
useZeroSettleEvents({
  onEntitlementsDidUpdate: (entitlements) => {
    updatePremiumUI(entitlements);
  },
});
```

```dart Flutter
// Listen to the entitlement update stream
ZeroSettle.instance.entitlementUpdates.listen((entitlements) {
  updatePremiumUI(entitlements);
});
```

</CodeGroup>

## Cancel Flow

Present a cancellation questionnaire before a user cancels their subscription. The flow collects feedback, optionally shows a retention offer, and returns the outcome.

The questionnaire and retention offer are configured on the [ZeroSettle dashboard](/iap/cancel-flow) — no code changes needed to update questions or offers.

### Built-in Cancel Flow

Call `identify()` once at startup — the imperative cancel flow takes no
`userId` on iOS and Flutter. React Native (1.3.x) still passes a `userId`.

<Note>
  The imperative `presentCancelFlow` is implemented on **iOS only**. The
  Flutter and React Native `presentCancelFlow` calls work when the app runs on
  iOS; on Android they are not available. On Android, render the
  `ZeroSettleCancelFlow` Composable or use the headless cancel-flow primitives —
  see the [Cancel Flow API](/iap/custom-cancel-flow).
</Note>

<CodeGroup>

```swift Swift
Button("Cancel Subscription") {
    Task {
        let result = await ZeroSettle.shared.presentCancelFlow(
            productId: "premium_monthly"
        )
        switch result {
        case .cancelled:
            showConfirmation("Your subscription has been cancelled.")
        case .retained:
            showConfirmation("Thanks for staying!")
        case .paused(let resumesAt):
            showConfirmation("Your subscription is paused.")
        case .dismissed:
            break
        }
    }
}
```

```kotlin Kotlin
// Android renders the cancel flow with the ZeroSettleCancelFlow Composable
// from the :ui module. Fetch the config, render it, then act on the result.
scope.launch {
    val config = ZeroSettle.fetchCancelFlowConfig().getOrNull() ?: return@launch
    // Render ZeroSettleCancelFlow(config = config) { result -> ... }
    // On a terminal CancelFlow.Result, call the matching headless method:
    //   CancelFlow.Result.SaveOfferAccepted -> ZeroSettle.acceptSaveOffer(...)
    //   CancelFlow.Result.Paused            -> ZeroSettle.pauseSubscription(...)
    //   CancelFlow.Result.Cancelled         -> ZeroSettle.cancelSubscription(...)
}
```

```dart Flutter
// iOS only — see the Note above. Identity is implicit; no userId.
final result = await ZeroSettle.instance.presentCancelFlow(
  productId: 'premium_monthly',
);
switch (result) {
  case CancelFlowCancelled():
    showConfirmation('Subscription cancelled.');
  case CancelFlowRetained():
    showConfirmation('Thanks for staying!');
  case CancelFlowPaused():
    showConfirmation('Subscription paused.');
  case CancelFlowDismissed():
    break;
}
```

</CodeGroup>

### Cancel Flow Results

| Result | Description |
|--------|-------------|
| `cancelled` | User completed the flow and cancelled their subscription |
| `retained` | User accepted the retention offer and kept their subscription |
| `paused` | User chose to pause their subscription instead of cancelling |
| `dismissed` | User dismissed the flow without completing it |

On Android, the `ZeroSettleCancelFlow` Composable emits `CancelFlow.Result`
values — `Cancelled`, `Paused(resumesAt)`, `SaveOfferAccepted(productId)`, and
`Dismissed`. `SaveOfferAccepted` is the Android equivalent of `retained`.

<Tip>
  Configure the cancellation questionnaire and retention offers from the ZeroSettle dashboard. You can update questions and offers without an app update.
</Tip>

### Pause Option

Pause lets subscribers temporarily stop their subscription instead of cancelling outright. When enabled, the cancel flow can present a pause page where the user picks a pause duration.

- **Dashboard-configured**: Enable pause and set available durations from the [ZeroSettle dashboard](/iap/cancel-flow). No code changes required.
- **Answer option trigger**: Individual answer options in the questionnaire can set `triggersPause` to route the user to the pause page instead of the retention offer.
- **Resume date**: The `paused` result includes an optional `resumesAt` date indicating when the subscription will automatically resume.
- **Entitlement state**: While paused, the user's entitlement reflects `status == .paused` with a `pauseResumesAt` date. Access is revoked during the pause period and restored automatically when the subscription resumes.

## What Customers Can Do

In the Stripe customer portal, customers can:

- **See upcoming payment information** — View details about their next billing cycle
- **Cancel a subscription** — End their subscription with immediate effect or at period end
- **Change subscription products** — Upgrade or downgrade to different subscription tiers
- **Re-subscribe** — Reactivate a cancelled subscription before it expires
- **Update payment methods** — Change or add new payment methods
- **View payment history** — See a complete list of all past payments
- **Download receipts and invoices** — Get PDF receipts and invoices for their records

## Email Links

Customers can also access their portal through links included in emails that ZeroSettle sends automatically:

- **Subscription confirmation** emails
- **Renewal receipt** emails
- **Billing issue** notifications

Each email contains a "Manage Subscription" link that opens the Stripe-powered billing portal.

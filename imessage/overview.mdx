Send and receive iMessages through a dedicated phone number, from code.
The same number and API support [SMS fallback](/imessage/send-a-message#sms-fallback) for eligible one-to-one texts to phones without iMessage, including Android.
This page is for agents and developers integrating the API.

[Get a number](https://portal.zerosettle.io/imessage) · [Read as markdown](https://portal.zerosettle.io/docs.md)

<Tip>

Agents: fetch the raw markdown at [`GET /docs.md`](https://portal.zerosettle.io/docs.md) (no auth) and read it
in one go. Every example uses `$BASE` (the API origin, e.g.
`https://portal.zerosettle.io`) and `$TOKEN` (your bearer).

</Tip>


## Set it up with your AI agent

Paste this into Claude Code, Cursor, ChatGPT, Grok, or any agent with a shell.
It wires up everything: the token check, a signed webhook receiver, a tunnel,
registration, and a test message. Fill in the two placeholders first.

```text Agent prompt
You are wiring up a ZeroSettle iMessage line for me. Base URL: https://portal.zerosettle.io
My API token: PASTE_TOKEN_HERE
Where my code runs: DESCRIBE_YOUR_STACK (e.g. "a Python FastAPI app", "a Next.js app on Vercel", "nothing yet — pick something simple")

Do this end to end, and show me each result:
1. Read the full API reference at {BASE}/docs.md before writing any code.
2. Verify the token with GET {BASE}/api/imessage/line and tell me my line's number and whether it is paid. If you get 402, stop and tell me to subscribe in the console at {BASE}/imessage.
3. Build a webhook receiver in my stack that: reads the raw request body; verifies X-ZeroSettle-Signature exactly as the docs describe (HMAC-SHA256 of "<t>.<raw body>", 300 s tolerance, constant-time compare); deduplicates on message.id; returns 200 within a second; and handles ONLY event == "message.received" (ignore message.sent, message.failed, and reaction.* except for logging). Persist inbound messages somewhere durable.
4. Expose it on a public HTTPS URL (use cloudflared or ngrok if I have no deployment), then register it with PUT {BASE}/api/imessage/webhook. Store the returned secret in my environment as ZEROSETTLE_WEBHOOK_SECRET — it is shown once. Never print it into a chat transcript or commit it.
5. Send me a test message with POST {BASE}/api/imessage/send to my own number (ask me for it), then confirm the message.sent event arrived at the webhook and that a reply from my phone arrives as message.received. Photos and voice messages go through the same endpoint (image_b64 / audio_b64, see the Attachments section); an inbound photo arrives as kind "image" with an image.url you fetch with the same bearer. A video (up to a minute) is uploaded first with POST {BASE}/api/imessage/videos and sent with video_id once it is ready, for 1 credit per 3 MB per recipient; an inbound video (1 per 3 MB too) arrives as kind "video" with a video.url that redirects to the file.
6. Add a helper to react with POST {BASE}/api/imessage/reactions and a fallback poller using GET {BASE}/api/imessage/messages?after_id=… for when the webhook is down.
7. Respect the limits: new contacts per number are 5 a day on Pro, and 3 per 15 minutes and 50 a day on Growth (people who text first don't count; each number allows 10,000 messages a day, sent and received, with known contacts); handle 429 by waiting error.retry_after_s and showing me error.message (on Pro it says how to get more: upgrade to Growth in the console, $199 a month per number); never send more than 2 message bursts (messages within 5 minutes of the burst's first message count as one) to someone who hasn't replied — the API returns 403 awaiting_reply; send only text (no photos, videos or voice messages) to someone who has never replied — 403 attachment_before_reply. The send endpoint attempts iMessage first. SMS fallback can deliver eligible plain-text messages to phone numbers without iMessage, including Android. Check message history for the eventual transport. Read the SMS fallback section for eligibility and supported messages. ZeroSettle sends only your supplied text; include any opt-out instructions you need. GET /api/imessage/availability checks iMessage registration without sending; it does not report whether this account has SMS enabled. Treat 402 as "stop and tell me". Honor STOP/unsubscribe replies by never messaging that handle again (the API enforces it too: a send to them returns 403 recipient_opted_out; don't retry it). Only message people who consented — read the compliance section and remind me of it.
When done, give me a short runbook: how to run it, where the secret lives, how to rotate the token, and how to check the last webhook delivery via GET {BASE}/api/imessage/line.
```

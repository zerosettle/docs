---
title: "Switch from Photon"
---

Moving from Photon to ZeroSettle is one pass for your AI agent: it finds
your Photon SDK calls and event listeners, rewrites them against this API, moves your webhook, and tests the
result on your own phone before removing Photon. Get your number and an API
token in the console at `/imessage` first, then open your project in Claude
Code, Cursor, ChatGPT or Grok and paste this.

```text Agent prompt
I'm moving my iMessage integration from Photon to ZeroSettle. ZeroSettle base URL ({BASE}): https://portal.zerosettle.io
My ZeroSettle API token: PASTE_TOKEN_HERE. Put it in my environment as ZEROSETTLE_TOKEN; never commit it or print it.

1. Read the full ZeroSettle API reference at {BASE}/docs.md before changing any code.
2. Check the token with GET {BASE}/api/imessage/line (header Authorization: Bearer <token>) and tell me my new number (handle). On 402, stop and tell me to subscribe in the console at {BASE}/imessage.
3. Find every Photon touchpoint and list them for me before editing: the spectrum-ts, @spectrum-ts/*, @photon-ai/advanced-imessage, @photon-ai/advanced-imessage-kit and @photon-ai/imessage-kit packages; Spectrum(...), createClient(...) and SDK({ serverUrl, apiKey }) setup; PHOTON_* env vars; and every place that sends, reacts, shows typing, manages groups or listens for messages.
4. Put ZeroSettle behind one small module in my stack (plain HTTPS and JSON, no SDK) and map each call:
   - Chat GUIDs: "iMessage;-;+15551234567" (and "any;-;…" or "SMS;-;…") becomes the handle "+15551234567", a phone number or iMessage email. A group "iMessage;+;chat…" becomes chat_id, in the same format.
   - sendText / sendMessage → POST {BASE}/api/imessage/send {to, text}. effectId → effect (slam, loud, gentle, invisible_ink, echo, spotlight, balloons, confetti, love, lasers, fireworks, celebration, shooting_star). selectedMessageGuid → reply_to (a ZeroSettle message id or guid).
   - attachments.upload + sendAttachment → the same send with image_b64 + image_format (photo) or audio_b64 + audio_format (voice message). A video is uploaded with POST {BASE}/api/imessage/videos and sent with video_id once it is ready (1 credit per 3 MB, per recipient).
   - setReaction → POST {BASE}/api/imessage/reactions {message_id, reaction}: love, like, dislike, laugh, emphasize or question, prefixed with remove_ to take one back. message_id is the ZeroSettle id, so keep it from the send response or the webhook.
   - setTyping → POST {BASE}/api/imessage/typing {to, state: "start" | "stop"}.
   - chats.create with several addresses → POST {BASE}/api/imessage/groups {to, text, name}; setDisplayName / addParticipants → POST {BASE}/api/imessage/groups/update.
   - edit and unsend have no ZeroSettle equivalent: show me where my code uses them.
5. Replace the live connection (subscribeEvents, sdk.on("new-message"), the gRPC or Socket.IO stream) with a webhook receiver. Register it with PUT {BASE}/api/imessage/webhook {url} and store the returned secret as ZEROSETTLE_WEBHOOK_SECRET (it is shown once). Verify X-ZeroSettle-Signature on the raw body (HMAC-SHA256 of "<t>.<raw body>", 300 s tolerance, constant-time compare), dedupe on message.id + event, answer 2xx within 10 s, and act only on event "message.received" (my own sends come back as message.sent; answering those loops). message.handle is the sender, message.text the text, message.chat_id the group; an inbound photo, voice message or video arrives as kind image, audio or video with a url fetched with the same bearer. catchUp(since) after a disconnect becomes GET {BASE}/api/imessage/messages?after_id=<last id>. With no public URL, use cloudflared or ngrok in development, or the docs' polling recipe.
6. Handle what differs. Read the SMS fallback section for availability and supported content. The same plain-text send prefers iMessage and falls back to SMS when available; SMS records carry service: "SMS", and the first successful SMS per account/recipient adds a separate opt-out notice. The send API does not fall back to RCS or MMS. GET /api/imessage/availability checks only iMessage registration without sending. New contacts per number: 5 a day on Pro, 3 per 15 minutes and 50 a day on Growth; people who text first don't count, and each number allows 10,000 messages a day, sent and received, with known contacts. On 429 wait error.retry_after_s and log error.message. At most 2 messages to someone who hasn't replied (403 awaiting_reply), text only until they reply (403 attachment_before_reply), and never a message to anyone who texted STOP (403 recipient_opted_out). A number sends one message at a time: on 429 line_busy, retry after 2 s. Only message people who consented; read the compliance section and remind me of it.
7. My contacts will see a new number, and each is a new contact to it until they text it. Write me a short heads-up to send from the old number asking them to text the new one.
8. Update tests and fixtures to the ZeroSettle shapes and run them. Send a test message to my own number (ask me for it), confirm message.sent reached the webhook, and that my reply arrives as message.received. Only then remove the Photon packages, code and env vars.
9. Finish with a short runbook: how to run it, where the token and webhook secret live, how to rotate them, and how to check the last webhook delivery with GET {BASE}/api/imessage/line.
```

## June 2026

<Update label="1.7.0" description="2026-06-10">
### Trial billing facts and Apple external-purchase compliance (iOS)

1.7.0 raises the native SDK floors to ZeroSettleKit `~> 1.5.2` (iOS) and `zerosettle-android 1.2.1` (Android) and surfaces their new `TrialFacts` through the Dart layer. `Product.trial` carries the trial mode, amounts, and duration your paywall needs to render accurate copy. iOS apps in the EU, EEA, or Japan inherit automatic Apple external-purchase token minting from the ZeroSettleKit 1.5.2 floor bump with no Dart-side changes required; you should follow the [native setup guide](https://docs.zerosettle.io/iap/external-purchase) for Apple program enrollment and the required entitlements and `Info.plist` keys.

- **Feature**: `TrialFacts` Dart class — `mode: ZSTrialMode` (`.free` / `.paid` / `.authHold`), `duration: String?`, `upfrontAmountCents: int`, `holdAmountCents: int`, `validatesCard: bool`; `fromMap()` returns `null` on unknown `mode` values (forward-compatible)
- **Feature**: `ZSTrialMode` enum — Dart mirror of the native trial-mode type, with `fromRawValueOrNull()` factory
- **Feature**: `Product.trial: TrialFacts?` — bridges native `ZSProduct.trial` (iOS) and `Product.trial` (Android) via both platform bridges; `null` when no trial is configured or the user ID was omitted from product fetch
- **Improvement**: iOS floor raised to ZeroSettleKit `~> 1.5.2` — inherits automatic Apple external-purchase token minting for EU/EEA/Japan; Android floor raised to `zerosettle-android 1.2.1`
</Update>

<Update label="1.6.0" description="2026-06-01">
### `OfferImpression` widget and `reportOfferViewed`

Flutter wrapper for the offer impression system that shipped in ZeroSettleKit 1.5.0 and ZeroSettle-Android 1.2.0. Wrap a custom offer banner with `OfferImpression(child: ...)` to automatically fire an impression event when it becomes ≥50% visible. Call `ZeroSettle.reportOfferViewed(...)` directly for fully headless integrations. `ZsOfferTipView` (the built-in native widget) tracks itself and should **not** be wrapped.

- **Feature**: `OfferImpression` widget — wraps any custom offer banner and auto-reports a `POST /v1/iap/offer-viewed/` impression event when ≥50% visible, once per appearance
- **Feature**: `ZeroSettle.reportOfferViewed(productId?, variantId?, flowType?)` — static, fire-and-forget impression event for custom offer UIs; resolves the active offer automatically when parameters are omitted
</Update>

## May 2026

<Update label="1.5.1" description="2026-05-25">
### Soft-deprecate `setEclAvailabilityOverride`

`setEclAvailabilityOverride` (introduced in 1.5.0) is immediately soft-deprecated in favor of `setSwitchAndSaveTestMode`, which simulates the full Switch & Save flow end-to-end rather than just the offer gate. The method remains callable; it will be removed in 2.0.

- **Improvement**: `ZeroSettle.instance.setEclAvailabilityOverride` deprecated — use `setSwitchAndSaveTestMode` for complete end-to-end Switch & Save testing
</Update>

<Update label="1.5.0" description="2026-05-22">
### Android Play transfer simplification and Switch & Save test-mode

Aligned with ZeroSettle-Android 1.1.0. `transferPlayOwnershipToCurrentUser` now takes only `productId` — the Play purchase token is sourced automatically from the matching `PendingClaim`. Two new helpers let developers exercise the Switch & Save flow on non-ECL-enrolled Android devices.

<Warning>
  **Breaking change (Android only):** `transferPlayOwnershipToCurrentUser(productId: ..., originalTransactionId: ...)` is now `transferPlayOwnershipToCurrentUser(productId: ...)`. Remove the `originalTransactionId:` named argument from call sites.
</Warning>

- **Breaking**: `transferPlayOwnershipToCurrentUser` drops the `originalTransactionId` named parameter — the Play purchase token is resolved internally (Android only; iOS unaffected)
- **Feature**: `ZeroSettle.instance.setSwitchAndSaveTestMode(bool)` — fakes Play ECL plumbing so the full Switch & Save flow runs on non-ECL Android devices
- **Feature**: `ZeroSettle.instance.setEclAvailabilityOverride(bool?)` — override the ECL availability gate (deprecated in 1.5.1; prefer `setSwitchAndSaveTestMode`)
- **Feature**: `PendingClaim.purchaseToken: String?` — new optional field carrying the Play purchase token for Android ownership transfer
</Update>

## 1.x

<Update label="1.4.0" description="Current">
### Android-parity sweep & SDK event stream

- **Android parity**: Closes the remaining native bridge gaps — `getSdkVersion()`, User Choice Billing state (`getIsUcbEnabled()` / `isUcbEnabledUpdates`), `releasePendingCheckout()`, and the pending-actions APIs (`getPendingActions()`, `pendingActionsUpdates`, `dismissPendingAction()`).
- **SDK event stream**: New `ZeroSettle.instance.events` — a `Stream<ZeroSettleEvent>` of analytics and lifecycle events with typed variants.
- **User offers**: `fetchUserOffer()` returns a typed `UserOfferResponse` — the server-canonical migration / upgrade decision.
- **New widgets**: `ZeroSettlePendingActionBanner` and `ZeroSettleOfferTip` (both Android-rendered; iOS renders nothing).
- All changes are additive — no public API was renamed or removed.

For the full, authoritative changelog see `CHANGELOG.md` in the [ZeroSettle-Flutter repository](https://github.com/zerosettle/ZeroSettle-Flutter).
</Update>

<Update label="1.0.0 — 1.3.x" description="Identity-first API">
### Identity-first API and unified purchase

- **`identify()`**: User identity is now established once via `ZeroSettle.instance.identify(Identity.user(id: ...))` instead of passing `userId` to every call. The per-call `userId` parameter and `bootstrap()` are deprecated and removed in 2.0.
- **Unified `purchase()`**: A single `purchase(productId:)` entry point routes to web checkout or native StoreKit / Play Billing automatically.
- **Pending claims & ownership transfer**: `getPendingClaims()`, `transferStoreKitOwnershipToCurrentUser()` (iOS), and `transferPlayOwnershipToCurrentUser()` (Android).
- **Apple Pay**: `presentApplePaySetup()`, `getApplePayState()`, and the `applePayStateUpdates` stream.
</Update>

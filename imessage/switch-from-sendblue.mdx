---
title: "Switch from Sendblue"
---

Moving from Sendblue to ZeroSettle is one pass for your AI agent: it finds
your Sendblue API calls and webhook handlers, rewrites them against this API, moves your webhook, and tests the
result on your own phone before removing Sendblue. Get your number and an API
token in the console at `/imessage` first, then open your project in Claude
Code, Cursor, ChatGPT or Grok and paste this.

```text Agent prompt
I'm moving my iMessage integration from Sendblue to ZeroSettle. ZeroSettle base URL ({BASE}): https://portal.zerosettle.io
My ZeroSettle API token: PASTE_TOKEN_HERE. Put it in my environment as ZEROSETTLE_TOKEN; never commit it or print it.

1. Read the full ZeroSettle API reference at {BASE}/docs.md before changing any code.
2. Check the token with GET {BASE}/api/imessage/line (header Authorization: Bearer <token>) and tell me my new number (handle). On 402, stop and tell me to subscribe in the console at {BASE}/imessage.
3. Find every Sendblue touchpoint and list them for me before editing: the sendblue npm and PyPI packages, calls to api.sendblue.co or api.sendblue.com, the sb-api-key-id / sb-api-secret-key headers, SENDBLUE_* env vars, from_number and sendblue_number settings, status_callback URLs, and the webhook handlers Sendblue posts to.
4. Put ZeroSettle behind one small module in my stack (plain HTTPS and JSON, no SDK) and map each call:
   - POST /api/send-message {number, content} → POST {BASE}/api/imessage/send {to, text}. send_style → effect, same names except invisible → invisible_ink. reply_to.message_handle → reply_to (a ZeroSettle message id or guid). from_number → line_id (or line), only if I have more than one ZeroSettle number.
   - media_url → download the file and send it base64 in the same call: image_b64 + image_format (photo) or audio_b64 + audio_format (voice message), with text as the caption. A video is uploaded with POST {BASE}/api/imessage/videos and sent with video_id once it is ready (1 credit per 3 MB, per recipient).
   - status_callback → the send result plus message.sent / message.failed webhooks for line acceptance. Delivery status polling for 1:1 iMessages → GET {BASE}/api/imessage/messages/delivery?ids=<message IDs>. message_handle → the ZeroSettle message id (and guid).
   - send-group-message and group_id → chat_id on the same send; start groups with POST {BASE}/api/imessage/groups {to, text, name} and change them with POST {BASE}/api/imessage/groups/update.
   - Typing indicators → POST {BASE}/api/imessage/typing {to, state: "start" | "stop"}; reactions → POST {BASE}/api/imessage/reactions {message_id, reaction}.
   - evaluate-service (the iMessage lookup) → GET /api/imessage/availability, which checks iMessage registration without sending; it does not report carrier SMS reach or account access. Inspect message.service == "SMS" in message history for an actual outgoing SMS. Contacts that had to be created before sending → nothing to create.
   - app_card has no ZeroSettle equivalent: show me where my code uses it.
5. Replace the Sendblue webhooks with one URL that gets every event: PUT {BASE}/api/imessage/webhook {url}, adding "typing_events": true only if my code used Sendblue's typing_indicator webhook. Store the returned secret as ZEROSETTLE_WEBHOOK_SECRET (it is shown once). Verify X-ZeroSettle-Signature on the raw body (HMAC-SHA256 of "<t>.<raw body>", 300 s tolerance, constant-time compare), dedupe on message.id + event, answer 2xx within 10 s, and act only on event "message.received" (my own sends come back as message.sent; answering those loops). Map the receive payload: content → message.text; from_number / number → message.handle; is_outbound → message.direction ("in" or "out"); group_id → message.chat_id; message_handle → message.guid; media_url → kind image, audio or video with a url fetched with the same bearer; opted_out → nothing to track, ZeroSettle blocks sends to anyone who texted STOP.
6. Handle what differs. Every direct text attempts iMessage first. SMS fallback can deliver eligible one-to-one text as SMS from the same number when iMessage is unavailable. Check outgoing message history for message.service == "SMS" to verify that transport. ZeroSettle adds no automatic opt-out text or separate follow-up; ignore outbound events when replying. Read the SMS fallback section for access and supported formats. Pro is inbound-only. Growth starts at 50 new contacts per day across the account, with options up to 500 per day, and has a rolling limit of 3 per 15 minutes per number. People who text first do not count toward the new-contact allowance. Each number allows 10,000 messages a day with known contacts, sent and received. On 429 for a Growth send, wait error.retry_after_s and log error.message. On Pro, people text us first. Show me how to upgrade to Growth if the integration needs to start conversations. At most 2 message bursts to someone who hasn't replied (messages within 5 minutes of the burst's first message count as one; 403 awaiting_reply), text only until they reply (403 attachment_before_reply), and never a message to anyone who texted STOP (403 recipient_opted_out). A number sends one message at a time: on 429 line_busy, retry after 2 s. Only message people who consented; read the compliance section and remind me of it.
7. My contacts will see a new number, and each is a new contact to it until they text it. Write me a short heads-up to send from the old number asking them to text the new one.
8. Update tests and fixtures to the ZeroSettle shapes and run them. Ask me to text my ZeroSettle number from my phone. Verify that message.received reaches the webhook, then reply using the API and confirm that message.sent reaches the webhook. Only then remove the Sendblue packages, code, env vars and webhooks.
9. Finish with a short runbook: how to run it, where the token and webhook secret live, how to rotate them, and how to check the last webhook delivery with GET {BASE}/api/imessage/line.
```

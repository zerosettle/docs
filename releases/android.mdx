## June 2026

<Update label="1.2.1" description="2026-06-09">
### Trial billing facts on `Product`

`Product` gains a new optional `trial: TrialFacts?` property mirroring `ZeroSettleKit 1.5.1`. When a user ID was supplied to `fetchProducts()` and the product has a server-configured trial, `trial` carries the billing mode, amounts, and duration your paywall needs to render accurate copy. On unknown `mode` values the field is `null` — a custom `NullableTrialFactsSerializer` absorbs unrecognized modes so the parent `Product` always decodes cleanly, keeping the SDK forward-compatible with new backend trial types.

- **Feature**: `TrialMode` enum — `FREE` / `PAID` / `AUTH_HOLD` with a `wire` string property and a `fromWireOrNull()` factory that returns `null` on unrecognized values
- **Feature**: `TrialFacts` — new public `@Serializable` data class with `mode: TrialMode`, `duration: String?`, `upfrontAmountCents: Int`, `holdAmountCents: Int`, and `validatesCard: Boolean`; wire keys follow `snake_case` via `@SerialName`
- **Feature**: `Product.trial: TrialFacts?` — decoded via `NullableTrialFactsSerializer`; `null` when absent or when the `mode` is unrecognized; additive alongside the existing `freeTrialDuration` / `isTrialEligible` fields
</Update>

<Update label="1.2.0" description="2026-06-01">
### On-screen offer impressions

Mirrors ZeroSettleKit 1.5.0. `ZeroSettle.reportOfferViewed()` fires a deduplicated `POST /v1/iap/offer-viewed/` event when an offer is viewed, using the new `sessionId` for once-per-session deduplication. `ZeroSettleOfferTip` (`:ui` module) tracks impressions automatically; `Modifier.offerImpression()` adds opt-in tracking to custom Compose offer UIs.

- **Feature**: `ZeroSettle.reportOfferViewed(productId, variantId?, flowType?)` — fire-and-forget offer impression report; safe to call from any thread
- **Feature**: `ZeroSettle.sessionId: String` — stable per-launch session identifier for impression deduplication
- **Feature**: `ZeroSettle.currentOffer: StateFlow<ResolvedOffer?>` — reactive current eligible offer, updated by `OfferManager`
- **Feature**: `Modifier.offerImpression()` (`:ui` module) — Compose modifier that auto-reports when a view is ≥50% visible
</Update>

## May 2026

<Update label="1.1.1" description="2026-05-25">
### Soft-deprecate `eclAvailabilityOverride`

`ZeroSettle.eclAvailabilityOverride` is deprecated in favor of `switchAndSaveTestMode`, which simulates the entire Switch & Save flow end-to-end — not just the offer gate. Existing code continues to compile with a deprecation warning; the property will be removed in 2.0.

- **Improvement**: `ZeroSettle.eclAvailabilityOverride` deprecated — migrate to `ZeroSettle.switchAndSaveTestMode` for full end-to-end Switch & Save testing on non-ECL devices
</Update>

<Update label="1.1.0" description="2026-05-22">
### Functional Play entitlement transfer, Switch & Save test-mode, and API simplification

`transferPlayOwnershipToCurrentUser` now resolves the Play purchase token internally from the matching `PendingClaim` — callers only pass `productId`. The SDK also gains `switchAndSaveTestMode` for end-to-end Switch & Save testing on non-ECL-enrolled dev devices, and it now reconciles owned Play purchases automatically on startup.

<Warning>
  **Breaking change:** `transferPlayOwnershipToCurrentUser(productId, originalTransactionId)` is now `transferPlayOwnershipToCurrentUser(productId)`. Remove the `originalTransactionId` argument from call sites — the SDK resolves the Play purchase token internally from `PendingClaim.purchaseToken`.
</Warning>

- **Breaking**: `ZeroSettle.transferPlayOwnershipToCurrentUser` signature simplified — `originalTransactionId` parameter removed; token is sourced from `PendingClaim.purchaseToken`
- **Feature**: `ZeroSettle.switchAndSaveTestMode: Boolean` — fakes Play ECL availability and attribution token so the full Switch & Save flow runs on non-enrolled dev devices
- **Feature**: `PendingClaim.purchaseToken: String?` — new optional field carrying the Play purchase token for ownership transfer
- **Feature**: SDK reconciles owned Play purchases automatically on `configure()`
- **Feature**: Full end-to-end Play entitlement transfer functional
</Update>

## 1.0.0

<Update label="1.0.0">
### Ground-up rewrite — parity with ZeroSettleKit (iOS)

`1.0.0` is a complete rewrite mirroring the current iOS `ZeroSettleKit` API. The pre-1.0 `0.x` line is yanked from Maven Central; see [Migrating from v0](/sdk/android/migration-from-v0) for the symbol mapping.

- **Identify-first surface**: `ZeroSettle.configure(context, ZeroSettleConfig(...))` then `ZeroSettle.identify(Identity.User / Anonymous / Deferred)`. No `bootstrap()`, no per-`userId` method overloads — every call resolves against the identified user.
- **Two artifacts**: headless `:core` (pure Kotlin + coroutines) and optional `:ui` (Compose components).
- **Unified `OfferManager`**: a single state machine for Switch & Save migrations (Play→web, StoreKit→web) and subscription upgrades, replacing the migration-only `ZSMigrationManager`.
- **Native Play Billing origination**: `purchaseViaPlayBilling()` plus a DataStore-backed persistent `PlaySyncQueue` and a defined [acknowledgement model](/sdk/android/acknowledgement-model).
- **Switch & Save for Play**: Play→web migration via Google's External Content Link (ECL) billing program (`ZeroSettle.launchSwitchAndSave(activity)`).
- **Pending actions**: backend-initiated prompts surfaced as a typed `PendingAction` sealed class on `ZeroSettle.pendingActions`, dismissed via `dismissPendingAction()`.
- **Cross-account claims**: `ZeroSettle.transferPlayOwnershipToCurrentUser(productId)` resolves a `PendingClaim`.
- **Reactive surface**: `StateFlow` (`entitlements`, `products`, `pendingActions`, `pendingClaims`, `isUcbEnabled`, …) and a `SharedFlow<ZeroSettleEvent>` (`events`) — no delegate interface.
- **Sandbox vs live** signalled purely by the publishable-key prefix (`zs_pk_test_` / `zs_pk_live_`).
</Update>
